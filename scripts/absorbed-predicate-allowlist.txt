# Format: <repo-relative-path>::<result>::<wide>::<narrow>  # reason
#
# The key names both predicate variables, not just the result, so an exception
# cannot leak onto an unrelated predicate that reuses a common result name.
# A reason is mandatory and stale entries fail the gate.
#
# An ordinary entry asserts that the absorption is DELIBERATE: the fallback is a
# substantive check in its own right and the strong path is only a stricter
# variant of it, so no contradiction can pass. It does NOT excuse a fallback
# that discards the strong path's evidence. If the strong path is the only
# thing verifying the claim the sub-gate's name makes, fix the predicate
# instead of listing it here.
#
# Ordinary entries must state why the weaker path is still sound.
# A reason starting KNOWN-DEFECT #397: instead records an UNFIXED defect
# tracked in issue #397, not a deliberate exception or a sound fallback.
# KNOWN-DEFECT reasons require an issue number; these entries are counted
# separately. Both kinds must match a current finding or fail as stale.
